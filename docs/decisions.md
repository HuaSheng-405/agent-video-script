# 设计决策记录（docs/decisions.md）

> 每条决策记录「选择 + 理由 + 代价」，是面试深挖的标准答案来源。
> 第 3 周主项目 v1.0 开工时，这里会长出更多条目。

## 2026-08 v0.2 验证性原型的 6 个决策

| # | 决策点 | 选择 | 理由 | 代价/风险 |
|---|---|---|---|---|
| 1 | 编排方式 | 父图固定流水线 + 编剧子图 | 视频脚本生产强顺序依赖，显式边可控可测评 | 灵活性低于 Supervisor，但本场景不需要 |
| 2 | 质检架构 | 规则层(代码) + LLM 打分层(1-5) | day06 实测 LLM 硬判 PASS/FAIL 会标准漂移（追着自己建议的钩子跑）；打分+中位数抗噪（RAGAS 方法论同源） | 规则层需校准，主观项仍有噪声 |
| 3 | 规则阈值 | 口播词 150~450 字（60 秒 ≈ 250 字） | 原 100~400 为拍脑袋，实测脚本含格式标记长 500+ 字连续误杀——阈值必须来自业务常识（语速 220-260 字/分）+ 实测分布 | 仍需按真实脚本微调 |
| 4 | 质检批注 | 必须可执行：「删减铺垫、保留钩子」而非「字数超标」 | 批注质量决定回退质量（day06 教训）；不可执行批注导致越改越差（实测：1087→429→558 开场被裁） | 批注模板需持续打磨 |
| 5 | 素材检索 | MCP 跨进程调用（llm env 检索 / python3.11 Agent） | 环境隔离、复用 rag-video-script 检索层、未来可多 Agent 共用（N+M） | 多一个进程就要管它的健康状态；工具为异步，整链必须 ainvoke |
| 6 | 回退策略 | ≤2 次后强制放行 | 防死循环烧 token（day06 retry_count 同构） | 极端情况输出非最优稿 |

## 踩坑记录（每坑一条工程铁律）

1. **MCP server 日志必须走 stderr**：print 进 stdout 会污染 JSON-RPC 协议流（实测 UnicodeDecodeError）
2. **含 MCP/网络工具的 Agent 整链必须 async**：StructuredTool 不支持同步调用（NotImplementedError）
3. **跨环境 MCP 版本必须一致**：client/server 协议握手会失败
4. **子图节点函数注解要用子图自己的 State**：外层 State 含 Annotated 通道时返回值会被 schema 丢弃
